# Contract: `registry` CLI

Run through `npm run registry -- <command>` (a `tsx` entry point).

| Command | Behaviour | Exit code |
|---|---|---|
| `registry check [--dir <root>] [--out reports]` (`<root>` contains `content/`, default `.`) | Load, validate, write `integrity-report.json` and `integrity-report.html` to `--out`. Prints a one-line summary and each error's rule ID. | `0` no errors (warnings allowed) · `1` one or more errors · `2` tool failure (unreadable directory) |
| `registry build --out <siteDir> [--dir <root>]` | The registry's part of a site build (T119a): runs the same gate as `check`; only if it passes, applies any specialist vocabulary mapping (TC-D016) and writes `_redirects` and `data/relations.json` (public referrers of public targets) under `--out`, then scans what it wrote for private values and non-public ids and removes it again if anything leaks. Nothing is written when the gate fails. A site integration calls this and nothing else. | `0` written · `1` gate failed or output leaked · `2` bad arguments |
| `registry mint <family> [--dir <root>]` | Prints the next unused `local-id` for the family; the highest number across the working tree and `main`, plus one. Does not create a file. | `0` · `2` unknown family |
| `registry scan <distDir> [--dir <root>]` | Leak scan: fails on any private value (plain, HTML-, JSON- or URL-escaped), any id of a non-public entity, any page address of one (`/<family>/<slug>` and the plural `/<family>s/<slug>` the site serves, with or without an anchor or a file under it), and the title of a non-public essay (spec 003 FR-006), in the built text output; also any editor report (`completeness.json`, `enrichment-queue.json`, `enrichment-queue.md`) as a file or as a name in a page (spec 004 US5). Private values are never printed. | `0` clean · `1` leak found · `2` the output directory or registry cannot be read |
| `registry synth <count> --seed <n> --out <dir>` | Writes a deterministic synthetic registry (`count` entities plus the seven rooms) under `<dir>`, for local timing. | `0` · `2` bad arguments |
| `registry promote <essay-id> <stage> --by "<person>" [--check] [--dir <root>]` | Moves an essay one editorial stage on, only if no error concerns it once the candidate is in place; rewrites its YAML with comments and key order kept. Specified in [spec 003 cli-additions.md](../../003-essay-framework/contracts/cli-additions.md). | `0` promoted (or `--check` would succeed) · `1` refused, rules named · `2` bad arguments or unknown essay |
| `registry completeness [--dir <root>] --out <dir>` | Writes the editor's `completeness.json`, `enrichment-queue.json` and `enrichment-queue.md` for every map record, public or held. A failing integrity gate is named on stderr but does not stop the reports. The files are never part of the site: `registry scan` fails if their names appear in the output. Specified in [spec 004 cli-additions.md](../../004-collection-catalogue/contracts/cli-additions.md). | `0` written (whatever the gate says) · `1` the registry cannot be loaded · `2` usage error |
| `registry new essay "<title>" --room <room> --question "<question>" --author "<name>" [--dir <root>]` | Writes a Concept essay record and an `.mdx` stub with a minted ID; removes both and exits `1` if the registry then has an error it did not have before. Specified in [spec 003 cli-additions.md](../../003-essay-framework/contracts/cli-additions.md). | `0` created · `1` not valid · `2` bad arguments, unknown room, unusable title |
| `registry import-bib <file> [--dir <root>] [--format bibtex\|ris\|csl-json] [--dry-run] [--out <dir>]` | Brings a reference manager's export in as held bibliography entries with minted IDs and CSL files; a work the registry already has is reported, never written; a file that does not parse is rejected whole with its line. Specified in [spec 006 import-bib-cli.md](../../006-bibliography/contracts/import-bib-cli.md). | `0` the file parsed (even if every item matched or was skipped) · `1` the file did not parse or the registry did not load · `2` bad arguments, unknown format, unreadable file |
| `registry import-legacy --snapshot <path> --profile v1 --out <dir> [--apply] [--dir <root>] [--dry-run]` | Stages the legacy site's records (all held) from a pinned snapshot, reports, runs the gate over staging; `--apply` adds only files that do not exist (spec 008). Exit 0 completed, 1 failed extraction, unmapped term or collision, 2 usage |
| `registry inventory --snapshot <path> [--dir <root>] [--out <file>]` | Lists every old URL of the snapshot with its one outcome, served in place by the archive or one redirect rule (spec 008). Exit 0, 1 on an unreadable snapshot |
| `registry archive-redirects [--dir <root>] [--out <file>]` | Writes the rule file for the archive project from the inventory and the registry; refuses an inventory that is out of date (spec 008). Never pushes. Exit 0, 1 when an entry cannot be resolved |

Output files are CI artefacts and are not committed. Warnings are printed with their rule IDs and counted in the summary but never change the exit code.
