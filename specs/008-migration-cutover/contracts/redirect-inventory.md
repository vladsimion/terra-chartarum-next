# Contract: redirect inventory and rule file

## Inventory (`migration/redirect-inventory.json`)

Built by `registry inventory --snapshot <path>` from the snapshot's routes (research R3), never the live site. One entry per old URL path (trailing-slash normalised):

```json
{ "path": "/collection/babylonian/", "kind": "collection-record", "outcome": "rule", "to": "/collection/babylonian/" }
{ "path": "/essays/cartography/", "kind": "essay", "outcome": "in-place" }
```

`outcome` is `in-place` (the archive serves it where it is) or `rule` (one redirect rule with a `to`). Sorted by path. A path appears once.

## Outcome policy

| Old route | Outcome |
|---|---|
| `/essays/<slug>/`, unrebuilt | `in-place` |
| `/essays/<slug>/`, rebuilt (the essay record has `legacy_url`, is published and released) | `rule` to `/essays/<new slug>/` |
| `/collection/<id>/`, `/cartographers/<id>/` for an imported record that is public at cutover | `rule` to the same path on the new site; `in-place` while the record is held |
| `/collection/`, `/cartographers/`, `/rooms/`, `/rooms/<slug>/`, `/about/`, `/colophon/`, `/essays/` | `rule` to the same path on the new site |
| `/bibliography` (one page, no per-entry pages) | `rule` to `/bibliography/` |
| `/atlas`, `/atlas/` and any query | `rule` to `/atlas/?from=legacy` |
| `/atlas/layers/<id>/` for an imported layer that is public at cutover | `rule` to `/atlas/?l=<id>` (the view address of that layer); otherwise `/atlas/?from=legacy` |
| `/atlas/handbook/**` | `in-place` until the Handbook text is final on the new site |
| `/`, `/privacy`, `/programmes/**`, `/series/**`, `/embeds/**`, `/data/**`, `/geo/**`, `/rss.xml`, `/search-index.json`, `/404`, `/500` | `in-place` |

A route with a public successor counterpart at cutover gets one rule; a route with none stays in place. The policy table is data in `src/migration/inventory.ts` and tested.

## Rule file (`archive/_redirects`)

Generated by `registry archive-redirects` from the inventory and the registry: Cloudflare `_redirects` syntax, one rule per `rule` entry, status 301, targets as absolute `https://terra-chartarum.org/…` URLs, sorted, with a header comment naming the snapshot SHA and the registry commit. A rebuilt essay's rule appears in the same pull request that publishes the essay. The command never pushes; the editor applies the file to the archive project by pull request and signs `redirect_switched` (ADR 0010).

## Zero-404 check

`cutover:check` reads the inventory and the rule file and fails on: an inventory path with `outcome: rule` that has no matching rule; a rule whose path is not in the inventory; a rule whose `to` is not a built page of the successor; two rules for one path.
