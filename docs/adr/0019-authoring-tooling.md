# ADR 0019 — Authoring tooling: editor schemas, the dependents graph, the link and manifest checker

**Status**: Accepted · **Date**: 2026-11-18 · **Jira**: TCX-60 (grill items 17, 19, 20), TCX-61, TCX-63, TCX-64 · **Epic**: TCX-59 (010) · **Extends**: ADR 0006 items 9 and 17, ADR 0003 §4

## Context
One maintainer writes every record, essay and dataset. The registry's rules are strict by design, and the grill's brief was to remove friction **without weakening any rule**. The integrity gate stays authoritative, and **no automation writes a canonical record directly**.

## Decision

### 1. Editor schemas (item 17)
- **What gets a schema:** every YAML record under `content/` gets a JSON Schema in VS Code, essays included, since essay records are YAML beside their MDX body.
- **Source:** the schemas are generated from the Zod schemas and are **not committed**. They are regenerated by `npm install`, `dev` and `build`, so Zod stays the only source and nothing can drift.
- **Hover text:** each value of a shared vocabulary (lifecycle, release, confidence, geometry provenance, silence state, locator state, evidence type) shows its `GLOSSARY.md` definition. A value with no definition fails the generator.
- **ID suggestions:** reference fields suggest existing IDs, with the title as description. Suggestions are regenerated on demand and may be stale between runs; an unknown ID still fails the gate.

### 2. The dependents graph (item 19)
- **One graph:** it is built from `referenceFields`, the same definition of a reference the gate and `reverse.ts` use, so there is one notion of "refers to".
- **It covers held records too**, which is what makes it different from the public "Cited in" and "Used by": the editor needs to see held work that a correction would touch.
- **Output:** written on every build as `dependents.json` (nodes and typed edges) plus a static HTML viewer. These are CI artefacts beside `integrity-report.json`, not committed and not deployed (ADR 0006 item 9).
- **Query:** `registry deps <id>` lists direct dependents and, separately, those reached through others, each with its edge type and path.
- **Not public in v1.** A public graph is a later spec, which would need a Principle IV statement, the ADR 0004 budgets and the held-leak rules.

### 3. Link and manifest checker (item 20)
- **What it checks:** the URLs records depend on:
  - URLs found in a locator's `consulted_copy`;
  - map image sources and institutional IIIF manifests (ADR 0011);
  - a bibliography entry's `digital_copy` (ADR 0014);
  - dataset source URLs.
- **When:** a weekly GitHub Actions workflow with per-host rate limits and retries. It is never part of the build or the gate, so an external outage cannot block a deploy (ADR 0006 item 17: the gate never touches the network).
- **On failure:** one Jira issue per broken URL, listing the records that use it, and not duplicated across runs. **A dead URL never changes a locator's `verified` state**, because verification records a reading that happened (ADR 0003 §4).
- **Changed manifests:** a manifest whose canvases changed (by ID or count) gets a separate, lower-severity review issue, since canvas references and Allmaps georeferences may now point at the wrong image. The fingerprints live in the workflow's cache, not in the repository.
- **Archived copies:** for a verified locator with no archived copy, the checker requests a web-archive snapshot and opens a pull request adding `archived_copy` (URL) and `archived_on` (ISO date) to the locator. A person merges it.

## Considered
- **Item 17:** validating only data collections (essay records are data too, so nothing is gained); committing generated schemas with a drift test; enums without definitions; no ID suggestions.
- **Item 19:** extending `reverse.ts` (it is deliberately public-only); Mermaid for the whole graph (unreadable at registry size); generating it only on demand (can be stale); a public page in v1.
- **Item 20:**
  - a derived link-status file shown to readers (adds reader-facing state for a rare event);
  - archived copies added only by hand;
  - treating any manifest change as a failure (noisy), or ignoring changes;
  - running daily (hard on library servers) or monthly (slow).

## Consequences
- The evidence locator gains optional `archived_copy` and `archived_on`, with valid and invalid fixtures.
- `GLOSSARY.md` gains **Archived copy** and **Dependents**.
- The repository needs a Jira API token and a GitHub token with `pull-requests: write` as Actions secrets.
- A VS Code YAML extension is recommended in `.vscode/extensions.json`; the editor features are a convenience, never a gate.
